# CineFlow 锁座与订单规则

## 适用范围

本文描述登录用户锁定座位、创建订单、取消订单以及锁定过期后的通用规则，不提供任何用户的实时订单或座位状态。

## 场次可售条件

- 场次必须真实存在。
- 场次状态必须为 `ON_SALE`。
- 场次开始时间必须晚于当前时间；已经开场的场次不可售。

## 锁座规则

- 锁座必须由已登录用户发起。
- 一次请求必须包含 1 到 8 个座位 ID，座位 ID 不得重复。
- 所有座位必须存在并属于请求的场次。
- 状态为 `SOLD` 的座位不能再次锁定。
- 状态为 `LOCKED` 且锁定者不是当前用户的座位不能再次锁定。
- 锁座成功后，座位状态变为 `LOCKED`，并记录锁定用户和过期时间。
- 默认锁座有效期为 5 分钟，实际值由 `seat_lock_minutes` 配置决定。
- 查询某个座位当前是否可用属于实时数据问题，必须调用 API 或查询数据库，不能仅根据本文回答。

## 创建订单规则

- 创建订单必须由已登录用户发起。
- `scheduleId` 必须大于 0，`idempotencyKey` 长度必须为 1 到 64 个字符。
- 同一用户重复提交相同的 `idempotencyKey` 时，返回已经创建的订单，不重复创建新订单。
- 创建订单时会再次检查场次和座位，并在数据库事务中锁定相关记录，以降低并发重复售票风险。
- 新订单初始状态为 `PENDING_PAYMENT`。
- 订单总金额等于场次单价乘以座位数量。
- 订单创建后，座位继续保持 `LOCKED` 并关联该订单；默认订单支付有效期为 15 分钟，实际值由 `order_expire_minutes` 配置决定。

## 过期与取消规则

- 系统发现座位锁定已经过期时，会把座位恢复为 `AVAILABLE`，同时清除锁定用户、过期时间和订单关联。
- 与过期座位关联且仍处于 `PENDING_PAYMENT` 的订单会变为 `EXPIRED`。
- 只有 `PENDING_PAYMENT` 订单可以取消，取消后订单状态变为 `CANCELLED`，相关座位恢复为 `AVAILABLE`。
- 用户只能查询和操作属于自己的订单；不存在或不属于当前用户的订单按“订单不存在”处理。

## 不在本文中的实时信息

本文不能回答某个具体场次是否仍在售、某个座位当前是否可买、某个用户订单当前状态或实际票价，这些信息必须通过 CineFlow API 或数据库实时查询。
